# pandas 里最容易让回测出错的地方

不是 API 教程，而是审查回测代码（自己写的、同事写的、AI 写的）时要逐条检查的清单。
每一条都会让结果**悄无声息地**变好看，而不是报错。

| # | 检查点 | 出错时的样子 | 怎么验证 |
| --- | --- | --- | --- |
| 1 | **按标签对齐，不按位置。** 两个 Series 运算时按索引配对，结果索引是并集 | 改了索引去“错开一期”，周末和节假日对不上，多出 NaN 或配错对 | 结果长度是否等于预期；用 `shift` 挪值而不是改索引 |
| 2 | **信号要晚一期才能用。** t 收盘才知道的信号，只能吃到 t+1 的收益 | `signal * returns` 没有 `shift(1)`，在随机数据上也能赚钱 | 在零漂移 GBM 上跑，Sharpe 应接近 0；改动第 t 天价格，第 t 天的仓位不应变 |
| 3 | **`shift(-k)` 是未来。** | 特征或信号里出现负的 shift | 全文搜索 `shift(-` |
| 4 | **滚动窗口包含当期。** `rolling(n)` 在 t 时刻用的是 t-n+1 … t | 用当天的滚动统计量做当天的交易决定 | 同第 2 条 |
| 5 | **全样本统计量泄漏未来。** 用整段数据的均值、标准差、分位数做标准化或阈值 | `(x - x.mean()) / x.std()` 出现在回测里 | 只能用 `expanding()` 或 `rolling()`，并且再 `shift(1)` |
| 6 | **`fillna` 的语义。** `ffill` 会把停牌期间的旧价格当成可成交价格；`fillna(0)` 把缺失收益当成 0 | 停牌、退市股票“平稳”地出现在组合里 | 检查缺失值是怎么产生的，再决定怎么填 |
| 7 | **`dropna` 改变样本。** 不同列的 NaN 位置不同，`dropna` 之后样本可能被悄悄截短 | 横截面只剩下“活下来的”股票（幸存者偏差） | 记录 `dropna` 前后的行数 |
| 8 | **重采样的标签和区间。** `resample("ME")` 的标签是月末，但数据可能在月末之后才可得 | 用月末标签的数据在月末当天交易 | 想清楚每个数据点**实际可得的时间** |
| 9 | **年化口径。** 日频交易日数据一年 252 期，周频 52，月频 12 | 用 365 或 `sqrt(len)` 年化 | 与 `quantlab.perf` 对照 |
| 10 | **重叠观测不独立。** 每天滚动的 n 日收益，相邻观测共享 n-1 天 | 用它算 t 值或回归标准误，显著性被放大约 $\sqrt{n}$ 倍 | 取不重叠的观测，或用 Newey-West 标准误 |

检查最有效的手段只有两个，适用于任何回测：

1. **在没有信号的数据上跑。** 零漂移 GBM、打乱顺序的收益。任何显著的结果都是 bug。
2. **改动未来，看过去变不变。** 把第 t 天之后（以及第 t 天本身）的数据换掉，t 之前的仓位和收益必须一模一样。
